# 参考项目笔记：simonlin1212/Vibe-Research

- 参考对象：<https://github.com/simonlin1212/Vibe-Research>（MIT，TypeScript + Python，约 728 文件 / 23MB）
- 阅读基准：仓库 `main` 于 2026-10-26 的快照（本地浅克隆后逐文件阅读）
- 编写时间：2026-10-28
- 用途：只记**可以搬过来的机制与纪律**，以及**不该照搬的部分**。不是对它的评测。

## 1 它是什么

A 股 / 美股 / 港股的本地投研工作台：浏览器页面 + 本机服务 + 六阶段研究编排器（profile → financials → estimates → valuation → risk → report）+ Python 取数层（168 个数据端点）+ 确定性计算库 `calc/`。研究线程用本机 Claude Code / Codex / CodeBuddy CLI 或任意 Chat Completions 接口当「大脑」，但受控工具、方法论、校验与合规 gate 是同一套。

关键分层（`AGENTS.md` 与 `methodology/constitution.md`）：

- **提示层**：研究宪法 + 技能包（`.agents/skills/`），每个阶段都塞进提示词，换哪个大脑都一样。
- **执行层**：受控工具（5 个：列文件 / 读文件 / 确定性计算 / 写阶段产物 / 写报告）、收工检查、`validator`、合规 gate。大脑**没有 Shell、没有网络、没有任意文件读写**。
- **取数在执行层完成**：编排器在每个阶段开始前跑完取数，大脑只读已落盘的证据。

这跟我们「纯函数解释引擎 + 确定性模板 + 校验」在方向上一致，但它把「不信任模型自述」写成了硬约束，并且在真实语料上量过误报。

## 2 与我们方案的重合点

| 它的做法 | 我们的对应 | 差异 |
| --- | --- | --- |
| 宪法 §0.1 禁止凭记忆生成行情/财务数字，必须有证据 id | 方案 §7.2「每个数字必须能回溯到事实或证据」 | 我们只校验摘要里的数字；它校验报告每一行 |
| 事实段与推断段分离，推断四档（已披露证实 / 有依据的推断 / 未核实线索 / 被反证） | 我们的四状态 `consistent / mixed / not_supported / untested` | **语义不同**，见 §4 |
| 口径提示（币种、TTM、报告期）只提示不拦截 | `meta.backgroundStale`、条件码白话、`missing` | 一致 |
| 报价时效不信任 agent 自填（交易日历 + 参考交易日 + 停牌判据） | `assessObservationQuality` 按天数 | 我们缺交易日历维度，见 §3 P1-4 |
| 产出红线 gate 对报告与**阶段产物**都生效 | `verifyExplanation` 只管摘要一句话 | 我们其它出口没有统一红线，见 §3 P1-5 |
| 只追加的审计链 + 明确「它证明不了什么」 | 不可变解释快照、`event_revisions` | 我们没有防篡改链，也没有等价免责说明 |

## 3 值得搬的（按性价比排序）

### P0-1 无出处的数字只替换那一个，不整段回退

它的问题定义值得抄：`orchestrator/src/number_gate.ts` 开头写「一个数字没出处，不该连累整段回答」，做法是把那个数字（连同紧跟的单位）换成「（略※）」，末尾加一条说明。

我们现在是 `verifyExplanation` 失败就整段回退模板（`compose.js`）。回退确实安全，但代价是：一句话里一个数字可疑，整段解释性文字消失。可以改成两级：

- 有出处 → 原样保留；
- 无出处 → 只把该数字替换成占位符，并记 `maskedNumbers`，界面照实说「有 N 处数字无法回溯，已略去」。

落点：`src/server/domain/explanations/compose.js`（新增 `maskUntraceableNumbers(summary, facts)`，`verifyExplanation` 保留为严格模式给测试用）。

### P0-2 算式自查（我们完全没有）

`orchestrator/src/arithmetic.ts` 的理由很硬：「引用来的数字可以跟已知值比对，**算出来的数字比不了**——它不等于任何一个已知值，于是成了唯一一类谁都没在看的数字」。真实案例：文字写「444.64 对 453.90，同比仅增 +0.2%」，实际是 −2.04%，方向都反了。

我们现在所有数字都是确定性模板算出来的，所以暂时不会错；但一旦允许模型改写「已给定事实」（方案 §7.2 的预留），这类自洽性错误就会出现。现在补一个纯函数成本很低：

- 识别文本里写出来的算式（`A÷B−1=R%`、`A−B=R` 之类），就地重算，对不上就点名；
- 明确**只查它自己写下的算式**，不判断算式选得对不对（拿错年份相除，算式本身可以自洽）。

落点：新增 `src/server/domain/explanations/arithmetic.js` + 测试；接进 `verifyExplanation`。

### P0-3 豁免清单要写明「每条豁免对应一次真实误伤」

它的 `number_fidelity.ts` 开头有一句纪律：正则里的每一条豁免都对应一次真实误伤（速率标签 1.6T、公告文号、HTTP 状态码、域名里的数字、时间窗口标签），改动前先看注释，不要「清理」掉。

我们的 `verifyExplanation` 现在是「摘要里所有数字都要在事实里找到」，没有豁免概念——将来摘要里出现「近 30 天」「(12,26,9)」「10-08」就会被判失败。抄它的做法：显式列出不核对的数字类别（日期 / 年份 / 编号 / 序号 / 时间窗口 / 括号参数组 / 写明「假设」的举例），每类写一行注释说明为什么，并用测试钉住。

落点：`compose.js` 增加 `NUMBER_EXEMPT` 规则常量；`tests/explanations.test.js` 加对应断言。

### P1-4 观测时效不只看「距今天数」

它的 `finance/quote_freshness.ts` 用「交易日历 + 参考交易日 + 盘前时段 + 成交量」判定陈旧，并且**只在判不了的时候说判不了**（`unknown_unverified`），不自填。

我们 `assessObservationQuality` 只有 `ageDays > tolerance` 这一条。后果：春节长假会让「完全正常」的日频序列被判 stale；反过来周末加上源延迟 1 天就是 fresh。我们没有交易所交易日历（`calendar.service.js` 是经济日历 FOMC/CPI），所以要做得先补一个轻量的交易日集合（可以用日线序列自身的工作日节奏 + 已知节假日表），再让质量判定读它。

落点：`src/server/domain/explanations/quality.js` + 新增 `src/server/domain/explanations/trading-days.js`。

### P1-5 措辞红线要覆盖所有出口

它把 gate 从报告扩到阶段产物，理由是「viewer 会把整个 record 放进 HTML、附录也会抄过去，调用方不看报告也照样收到建议」。实测 320 个真实阶段产物有 13 处命中，**全是合法内容**（免责声明里提到「目标价」），于是把阶段子串收窄到 3 项。

映射到我们：解释卡的渠道说明、图谱解释块（`graphExplanationBlock`）、地图播报（`impactBlockHtml`）、首页问题卡（`questionCardsHTML`）都是用户直接看到的文字，现在只有 `tests/understanding.test.js` 管解释卡那一份。应该把这套「不许出现证实/必然/概率/裸条件码」的断言提到共用，四个出口都跑。

落点：把断言抽成 `tests/helpers/wording.js`，四个出口各跑一遍。

### P2-6 规则收进来之前，先在真实语料上量误报

它的做法：每条正则都在 431 个真实产物上量过误报，**零命中才收进规则**；量的时候刷掉了 4 条候选（裸「合理价」会拒掉正确的免责声明，改为必须邻近数字）。

可复制成一道工序：拿现有解释快照 + 事件文本跑一遍措辞规则，统计命中，人工判定是否误伤，零误报才留。语料现成（`explanations` 表 50+ 快照、`event_revisions` 160+ 条）。

落点：新增 `scripts/measure-wording-false-positives.mjs`（只读，输出命中清单）。

### P2-7 「证明不了什么」要写在界面上

它的 `audit_chain.ts` 明确写：登记簿和数据在同一个文件夹，能改数据的人也能把整份登记簿按新内容重算一遍，链照样是通的；要防这个只能把链头另存到别处。界面上必须把这句话说出来，不能让人以为点一下「核对」就证明了一切。

我们对外称「不可变快照」，实际上同一个 SQLite 文件谁都能改。不需要建链，但需要在**方案 §14 与 README** 上加一句等价说明：快照保证「读取时不会被新规则重算」，不保证「内容没被人手工改过」。

## 4 不该照搬的

1. **架构**：它是 TS + Python 双运行时、plugin-per-vertical（餐饮垂类另有一套红线）、MCP、可换大脑、728 文件。我们是单进程 Node 服务（`node server.mjs`）+ 少量构建期依赖，用 `tests/client-modules.test.js` 这类契约测试守住分层。照搬架构的成本远超收益。
2. **推断四档不能替换我们的四状态**：它的四档说的是「这条**结论**有多可信」；我们的四状态说的是「这次窗口的**观测**与这条机制是否一致」。一个是认识论分级，一个是当期检验结果。混用会让「尚未确认」被读成「可信度低」，正是方案 §7.2 要避免的。要在文档里写清这层区别，防止后人合并两套词。
3. **`calc/` 那套计算库**：它解决的是估值链（扣非×4 PE、前瞻 CAGR、PEG 消化年数）。我们的计算只有对数收益、百分点差、bp 换算，没有估值链，引入只会增加口径面积。
4. **六阶段研究报告**：它是「研究一只股票」，我们是「解释一次变动」。阶段概念会把产品拉回研报形态，与方案 §3 的三层阅读冲突。

## 5 一句话结论

值得搬的是**四道工序**：数字只遮不整段回退、算式就地重算、豁免清单写清来源、规则先在真实语料上量误报。它们的共同点是把「模型可能说错」当成常态设计，而不是当成异常处理——这正是方案 §7.2 还差的一层。
