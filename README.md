## 启动

```bash
npm start          # 或 node server.mjs
```

然后打开 <http://127.0.0.1:8787>。

macOS 上也可以直接双击 `启动看板.command`：服务没起就起服务，已在跑就直接开页面。

环境变量：`PORT`（默认 8787）、`HOST`（默认 127.0.0.1）、`CACHE_TTL_MS`（默认 15000）。

## 依赖策略（2026-10 起）

项目已全面工程化，**取消「运行时零依赖」约定**：

- 前后端都可以引入成熟的 npm 依赖。选型门槛：维护活跃、提供 ESM、许可证与 MIT 兼容、体积与收益相称；引入时在对应设计文档里写明用途。
- 浏览器端依赖经 Vite 打包进 `public/vendor/`，产物入库 —— 所以 `node server.mjs` / 双击 `启动看板.command` 仍不需要先 `npm install`。
- 服务端若引入运行时依赖，要同步让 `启动看板.command` 在缺 `node_modules` 时自动执行 `npm ci`。
- 不变的底线：不依赖需要 API Key 或境外瓦片的在线地图服务，断网也能打开页面。

### 目前打进 vendor 的东西

| 产物 | 来源 | 大小（gzip） | 用途 |
| :--- | :--- | :--- | :--- |
| `vendor/macro-flow.js` | `src/client/views/macro/index.js` | 864KB（226KB） | `#/macro` 顶部的传导图谱（X6 + dagre），按需 `import()` |

业务代码**只写裸模块名** `import { geoPath } from 'geo-kit'`，两处解析：

- 浏览器：`public/index.html` 里的 `<script type="importmap">`（必须早于任何 `type="module"` 脚本）。
- Node / Vitest：`vite.config.js` 的 `resolve.alias`。

两边都由 `tests/geo-kit.test.js` 与 `tests/client-modules.test.js` 守着 —— 后者会从 `public/app.js` 出发做可达性遍历，只对**浏览器真正加载的模块**校验裸模块名，构建期子树（`src/client/views/macro/**`）不在其列。

`d3-selection` 与 `d3-transition` 必须落在同一个 bundle 里：后者靠 import 时的副作用给 `selection.prototype` 打补丁，分成两份实例会让动画静默失效。所以 d3 系依赖一律从 `geo-kit` 转出，不在业务代码里直接 import。

## 详情页

点任意一张卡片（或原油卡里的「布伦特」chip）进入该标的的详情页，`#/d/<id>` 可直接分享/收藏；点左上角「← 返回列表」或按 `Esc` 回到列表。

详情页包含：

1. **实时报价**：价格、涨跌额、涨跌幅、行情时间、实际命中的数据源
2. **区间涨跌**：近 1 日 / 1 周 / 1 月 / 3 月 / 6 月 / 1 年 / 3 年 / 年初至今，全部按日线收盘价现算
3. **历史走势图**：区间可切 1 年 / 3 年 / 5 年 / 全部，周期可切日 K / 周 K / 月 K（周月由日线本地聚合），**图型可切蜡烛 / 折线**，右侧整数档位价格轴，标注区间最高/最低点
4. **十字光标**：鼠标（或触摸）在图上移动，竖横虚线跟随，浮层给当根的开高低收、涨跌幅、实体、成交量、MA20/MA60，以及当天撞上的 FOMC/CPI 事件
5. **当日分时**：带昨收基准线，按时间轴绘制
6. **关键指标**（最多 24 项）：今开、昨收、最高、最低、振幅、成交量、成交额、换手率、52 周高低、距 52 周高/低、**RV20 / RV60 / 波动率分位**、全样本波动、历史最高/最低、MA20/60/120/250、单日最大涨/跌、连续涨跌天数
7. **内外盘对照**（国内金价专有）：国际金价 ÷ 31.1035 克/盎司 × 在岸美元人民币汇率，折成元/克后与上金所现货比较，给出内外价差。汇率与金价实时取自新浪 `fx_susdcny` 与东财 `122.XAU`
8. **多源对照**：同一标的不同数据源取价与偏差（用于判断源是否异常）
9. **历史日线表**：按时间倒序，每次展开 30 行，最多 5000 行

### 蜡烛图与十字光标

蜡烛用 `[开, 收, 高, 低]` 四价绘制，涨红跌绿（阳线 `--up` 实心、阴线 `--down` 实心）。几个实现要点：

- **y 轴范围必须吃进 high/low**，只按收盘价算会把上下影线裁掉。所以 `chartAxisOf` 支持传入 `hiLo` 扩展值域。
- **一根蜡烛占的横向槽位 **小于 1.5px 时跳过影线**，否则几千根竖线会糊成一片噪声。实体宽度夹在 1~11px。
- **坐标轴、网格、事件线、日期的画法和折线图共用 `chartAxisOf`**，两套渲染器如果各算一遍，叠起来就会错位（对数坐标下尤其明显）。
- 超过 320 根时页面提示「实体已压到 1px，看形态建议缩短区间或切周 K」。

十字光标对**折线和蜡烛都生效**。要点：

- SVG 用 `viewBox` + `width:100%`，实际渲染有缩放，所以要把 `clientX` 先除以 `rect.width / g.width` 换回 viewBox 坐标，再反推索引。
- 浮层默认在光标右侧，靠近右边界时**翻到左侧**；垂直方向夹在容器内。实测悬停最左 / 最右都不溢出（`left=20`、`right=1224`，容器 1224 宽）。
- 涨跌幅口径：东财源带 `pct`（百分数，1.23 表示 1.23%）；CBOE / Binance 源不带，就用**前一根收盘**自己算，保证每个标的都有涨跌幅。tooltip 里 `pct`（相对昨收）和「实体」（收−开）分开标注，因为跳空低开收高时两者会反号。

### 历史源降级与失败透出

东财会限流（实测整段返回空 / `fetch failed`），而它又是多数标的的唯一历史源。所以：

1. `buildDetail` 对每个标的都**补一路 Yahoo 历史兜底**（`inst.yahoo` 或从 `seed` 里捞 yahoo 符号），并把标普500 的 Yahoo 符号（`^GSPC`）补进实时源列表。
2. 每个源失败的原因记进 `history.errors`，历史为空时页面直接摊开：

```
历史数据暂时取不到：eastmoney — fetch failed；yahoo — HTTP 429: Too Many Requests
行情报价与关键指标仍然可用；等数据源恢复后会自动重试。
```

3. 降级后的实测表现：报价（涨跌额 / 涨跌幅 / 行情时间）、当日分时、今开 / 昨收 / 最高 / 最低 / 振幅**全部照常**，只有依赖历史的项（MA、52 周高低、RV、图表）为空 —— 而不是整页白屏。

### 详情接口

```
GET /api/detail/:id          # id: gold-cn | gold-intl | btc | oil | brent | sp500 | ndx100 | sh000001
GET /api/detail/:id?force=1  # 跳过 60 秒缓存
```

`daily` 字段用压缩数组以减小体积，顺序固定为：
`[日期, 开盘, 收盘, 最高, 最低, 成交量, 成交额, 涨跌幅%]`

## 刷新行为

- **每次打开页面**都会带 `force=1` 向数据源重新取一次，不读旧缓存；进入详情页同样强制拉一次。
- 页面驻留时每 15 秒轮询一次；切到其他标签页会暂停，切回来立刻补一次。
- 详情页每 30 秒刷新一次报价与历史（历史本身有 60 秒服务端缓存）。
- 右上角「刷新」按钮或按 `R` 可立即强制刷新。
- 服务端还有 15 秒缓存与后台定时刷新，避免多个页面重复打到上游。

## 为什么需要一个后端

新浪财经的行情接口不带 CORS 响应头，且要求 `Referer: https://finance.sina.com.cn`，浏览器无法直接请求；因此由 `server.mjs` 代理取数、归一化后再给前端。

```
浏览器 ──> /api/quotes ──> server.mjs ──> 新浪 / 东财 / Binance / Coinbase / gold-api
```

## 数据源与兜底

每个标的都配了多级数据源，主源失败会自动降级，并在卡片的 `meta` 行显示实际用到的源：

- 国内金价：`gds_AU9999` → `gds_AUTD`（黄金延期）→ `nf_AU0`（沪金连续）
- 国际金价：`hf_XAU` → `hf_GC`（纽约黄金）→ gold-api.com
- 比特币：Binance 主域 → Binance 备用域 → Coinbase 现货
- 国际原油：`hf_CL`（WTI）→ 东财 `102.CL00Y`（NYMEX 原油）
  - 卡内「布伦特」：`hf_OIL` → 东财 `112.B00Y`（布伦特当月连续），独立取数、独立兜底
- 标普500：`gb_$inx` → 东财 `100.SPX`
- 纳斯达克100：`gb_$ndx` → `gb_$ixic`（纳指综合，仅兜底）
- 上证指数：`sh000001` → `s_sh000001` → 东财 `1.000001`

全部源都失败时不会清空卡片，而是保留上一次成功值、置灰并标注「数据过期」，同时显示失败原因。

## 原油这一行为什么有两个价格

WTI 与布伦特是两个不同标的，但同属「国际原油」，所以放在同一张卡片里：右侧大号价格是 WTI（本行主标的，走势图也是它的），左列 chip 里的「布伦特」是附加上去的第二个报价，带自己的涨跌幅。

两个报价各自独立取数与降级——WTI 挂了不会连累布伦特，反之亦然。鼠标悬停 chip 可以看到它实际用的数据源和行情时间。

## 数据新鲜度

看板最怕的不是没数据，是**安静地显示一个旧值**——周末收盘、源延迟、停牌在界面上长一个样。

每个价格下面有一个新鲜度徽章，按市场状态分级：

| 状态 | 判定 | 颜色 |
| --- | --- | --- |
| `fresh` | 交易中且 ≤2 分钟 | 绿 |
| `normal` | 交易中 ≤15 分钟，或已收盘 ≤4 天 | 灰 |
| `delayed` | 交易中 15–60 分钟 | 黄 |
| `stale` | 交易中 >60 分钟，或已收盘 >4 天 | 红 |

分级不能用统一阈值：已收盘市场的"最后成交价"放 10 小时是正常的，而交易中超过 15 分钟就该警惕。所以 `gradeFreshness` 按 `marketStatus.open` 分开处理。

源的时间戳格式不统一（`"14:30:00"` / `"2026-10-26 14:30:00"` / `"2026-10-23"`），`parseDataTime` 统一解析；只有时间的会自动补当天日期，且源时间比现在晚时判定为昨天。币安 ticker 这类不给时间戳的实时推送单独识别为「实时推送」。

另外加了**异常值提示**：单日变动超过该标的常规区间（黄金 ±8%、BTC ±30%、VIX ±60%）时整行左侧加黄条，悬停看说明。这是脏数据的第一道防线。

## 统计严谨性

之前只给相关系数的点估计。**12×12 矩阵有 78 对，领先滞后再乘 11 个滞后约 1700 个检验——5% 显著性下纯随机也会跑出几十个「显著」。** 所以补了四层：

**1. Fisher z 置信区间**：每个系数给 95% CI，让你知道这个 0.32 的精度有多差。

**2. Newey-West 稳健标准误**：收益率有自相关和异方差，把相关系数看成 OLS 斜率，用 Bartlett 核加权残差自协方差，得到 HAC 标准误。同时保留朴素 p 值和 NW p 值，两者差得远就说明序列自相关严重。

**3. Benjamini-Hochberg 校正**：控制错误发现率（FDR），不是简单除以检验数量（Bonferroni 太保守，会漏掉真信号）。矩阵 78 对一起校正，领先滞后约 1700 个组合一起校正。

**4. 样本内外验证**：前 70% / 后 30% 分别算相关系数，符号必须一致才算「稳健」。

实测结果：

- **78 对中 56 对通过 BH 校正，其中 55 对样本内外同号**
- 最强的几对都是结构性的：VIX~VXN +0.939 `CI[0.92,0.95]`、WTI~布伦特 +0.924、标普~纳指 +0.922，全部 q≈0
- **抓到的典型假信号**：`黄金~布伦特` 朴素 p=0.0497「显著」，BH 校正后 q=0.193 不显著；`沪金~铜` 朴素 p=0.0009 但 q=0.066 仍不通过。这正是多重比较陷阱，不做校正就会把它们当成发现
- 领先滞后 6 条全部通过校正（q ≤ 0.011）

矩阵每格右上角 `*` 表示通过校正。点右上角「只看统计稳健」会把通不过的格子压暗到 26% 透明度——剩下能看清的才是真信号。

## 持久化

`data/` 下三样东西会落盘，重启不再从零开始：

| 文件 | 内容 | 作用 |
| --- | --- | --- |
| `llm-cache.json` | LLM 分类结果（按事件 id） | 重启不必重新调网关，省 token |
| `events/YYYY-MM-DD.jsonl` | 每天的事件归档 | 事件不再「过了就没了」 |
| `snapshots.jsonl` | 指标快照 | 供事后回溯与变化检测 |

LLM 缓存写入做了 3 秒 debounce（分类是逐批来的，攒一下再写）。超过 7 天的条目在加载时丢弃。

## 事件研究

事件中心的最后一节，回答一个很实际的问题：**这些日历事件日，市场波动真的比平时大吗？**

方法：事件日 `|日收益率|` vs 非事件日 `|日收益率|`，Welch t 检验，同时给中位数作稳健参考（收益率绝对值厚尾，t 检验偏宽松）。数据来自 BLS 官方 ICS 日历（2025-01 起）+ 美联储官网（2021 起）。

实测结论（lag=0，FOMC 43 个事件日）：

| 标的 | 事件日波动 | 普通日 | 倍数 | t |
| --- | --- | --- | --- | --- |
| 美元指数 | 0.51% | 0.35% | **1.49x** | **3.79** |
| 美债10Y | 6.06% | 4.18% | 1.45x | 2.18 |
| VIX | 8.22% | 4.81% | 1.71x | 2.14 |
| 黄金 | 1.06% | 0.78% | 1.37x | 1.96 |
| 标普500 | 0.98% | 0.79% | 1.24x | 1.41（不显著） |
| 纳指100 | 1.30% | 1.07% | 1.21x | 1.30（不显著） |

**FOMC 明显影响债市和汇率，但对股市影响不显著**——因为股市对 FOMC 的定价已经很充分（预期管理做完了）。这个结论比「FOMC 很重要」这种笼统说法有用得多。

CPI 样本只有 21 个事件日，全部不显著（t < 1.96），这是统计功效不足，不是「CPI 不重要」。页面上的 `n=` 标注就是给这个用的。

### T+0 / T+1 / 智能对齐

日历事件按**美东日期**标注，但资产收盘时点差别很大，直接全部用 T+0 会把反应归错日子：

- FOMC 美东 14:00 公布 ≈ 北京次日 02:00 / 03:00 → A 股次日开盘才交易
- CPI / 非农美东 08:30 公布 ≈ 北京 20:30 / 21:30 → A 股当日 15:00 已收盘

所以上证与沪金（上金所 Au99.99，日盘 09:00–15:30）对这类事件的口径是 **T+1**，其余资产当日即反应。页面默认「智能对齐」，格内标 `T+0` / `T+1`；也可以强制统一口径看错配长什么样。

这个口径差异直接改变结论。上证在 FOMC 的表现：

| 口径 | 倍数 | t |
| --- | --- | --- |
| T+0 | 0.63x | −3.32 |
| T+1（智能对齐） | 0.64x | **−4.83** |

两个口径都是 **比值小于 1**——FOMC 当日 A 股反而比平时安静。这不是"没传导"，是 A 股的波动主要由国内政策和流动性决定，美联储预期管理完成后对它的增量冲击很有限。T+1 口径下 t 值更负，说明"次日更平静"这个结果更稳健。

## 波动率（VIX / VXN）

列表第 8 行，主价 VIX，附带 VXN chip，和「原油 / 布伦特」同构。两者都能单独打开详情页。

| 指标 | 含义 | 数据源 | 历史 |
| --- | --- | --- | --- |
| VIX | 标普500 隐含波动率 | CBOE 官方 CSV | 9301 条，1990-01-02 起 |
| VXN | 纳斯达克100 隐含波动率 | CBOE 官方 CSV | 4307 条，2009-09-14 起 |

CSV 体积较大（VIX 约 300KB），所以统一走 10 分钟缓存，列表报价、详情历史、关联矩阵共用同一份解析结果。数值本身是 CBOE 每日收盘后更新，属于延迟数据。

VIX 自身的波动率高达 113%、历史最大回撤 −88.7%（2008 年 80+ 跌到 2009 年的 20+），这是正常的——它衡量的是别人的波动。

### 实现波动率（RV20 / RV60）与波动率状态

详情页给三个波动率，因为它们回答不同问题：

| 指标 | 用途 |
| --- | --- |
| **RV20** | 近 20 个交易日实现波动率 —— 当前环境 |
| **RV60** | 近 60 个交易日 —— 去掉短期噪声的趋势 |
| 全样本年化 | 只作参照 —— 横跨十几年的数被几轮危机平滑掉，没有决策价值 |

RV20 还会给出它在**过去 5 年滚动分布中的分位**，并落成一句话状态（极低 / 偏低 / 中性 / 偏高 / 极高）。交易员关心的是「现在偏热还是偏冷」，不是「历史平均是多少」。

实测标普500 详情页：`RV20 9.9% · 偏低 17 分位 / RV60 10.5% / 全样本 19.6%` —— 全样本 19.6% 看起来"很波动"，但当下其实处在五年里最低的五分之一。

### VRP（波动率风险溢价）

世界经济关联页顶部给 `VRP = VIX − 标普500 RV20`。

隐含波动率长期高于实现波动率，因为期权卖方要报酬。溢价被压到极低说明保护性期权便宜、市场自满；溢价飙升说明大家在抢买保护。

实测：`VRP +9.53 · VIX 19.45 − RV20 9.92`，隐含是实现的 1.96 倍。

## 全球市场地图

点右上角「全球地图」进入（`#/map`）。把「哪里在发生什么」和「哪个市场在动」放在同一张图上。

### 为什么用地图，而不是画在坐标纸上

因为金融市场的两个维度里，**位置和时间缺一不可**。第一版只用了位置（节点落在城市坐标），时间完全没表达——那块地换成白纸画点也成立，地图就白瞎了。所以补了两样只有地图能给的东西：

**1. 晨昏线（terminator）**。实时算太阳直射点（赤纬 + 经度），解 `cosH = -tan(lat)·tan(decl)` 得到昼夜分界的经度，画出环绕地球的 S 形曲线。配合节点的开市状态：**交易中的城市光环呼吸、已收盘的压暗**。一眼就能读出「现在谁在开着、谁在睡觉」——这是任何行情软件的单屏行情列表都做不到的。

**2. 事件冲击弧线**。地缘事件发生地 → 受影响交易所的贝塞尔曲线，`stroke-dasharray` 动画让光点沿线流动。把「中东出事 → 芝加哥原油、伦敦布伦特」这个因果画出来，而不是让用户自己在脑子里连。

连线目标由**事件自身的标的**决定，不是按区域硬编码。后端 `classify` 已经给每条事件标了 `symbols`（如 `['oil','gold-intl','vix']`），前端有一张标的 → 定价中心的映射表：

| 标的 | 定价中心 |
| --- | --- |
| `oil` | 芝加哥（WTI / CME）+ 伦敦（Brent） |
| `gold-intl` | 伦敦（定盘价）+ 纽约 |
| `gold-cn` | 上海（上金所） |
| `us10y` / `dxy` / `sp500` / `ndx100` / `btc` | 纽约 |
| `sh000001` | 上海 + 香港 |
| 各国股指 | 各自交易所（`n225`→东京、`dax`→法兰克福……） |

早期版本按区域写死（`me: ['ldn','bom']`），中东事件只连伦敦和孟买，漏掉真正定价的芝加哥原油，还会凭空连上不相关市场。现在弧线终点是实测反推的：`(-74,41)` 纽约、`(0,51)` 伦敦、`(-88,42)` 芝加哥。拿不到 `symbols` 时才退回区域兜底。

### 其余特性

- **14 个交易中心、20 个标的**直接标注，颜色随涨跌；同城多标的纵向堆叠
- **LOD 按缩放展开**：1.0× 每个城市只留 2 个标的（纽约显示「+3 放大可见」），1.5× 展开 4 个，2.2× 全开。否则纽约 5 行永远挤成一坨
- **平滑动画**：`requestAnimationFrame` + ease-out cubic 插值，缩放/平移有惯性收尾，不是瞬间跳变
- **双击放大**（GIS 标准手势）、滚轮以鼠标位置为中心缩放、拖拽平移、一键复位、原生全屏
- **节点就地展开卡片**：点城市浮出价格/涨跌/新鲜度卡片，点空白收起——不跳页，保住心流
- **新事件气泡**：轮询到新事件时在对应区域弹出，6 秒淡出，最多同时 3 个
- **右侧悬浮事件流**：可折叠，最新在上，新条目高亮闪一次
- **其他底图元素**：海洋径向渐变、经纬网格、177 国轮廓（描边随缩放保持 1px）
- **BTC 单独放卫星位**：24×7 无固定交易场所，硬套坐标是错的

**标签布局是这块最麻烦的事**。纽约 5 个标的、欧洲三国（伦敦/巴黎/法兰克福）、北美三城（纽约/多伦多/芝加哥）在地图上各自只隔十几像素，不手动错开会叠成一团。所以每个城市配了 `dx/dy` 偏移量和引导线，标签朝指定方向展开。

地图数据来自 `world-atlas` 110m TopoJSON，用 `tools/topo2svg.mjs` 一次性转成 177 个国家的 SVG path（130KB），前端零依赖直接渲染。

**两个必须处理的坑**：

1. **跨日界线国家会画出一条横穿全图的线**。俄罗斯、斐济这些多边形在 ±180° 处坐标从 1200 跳到 0，直接连线就是一条贯穿地图的直线。构建时检测到 x 跳变超过半张图就断开成独立子路径。
2. **SVG 里不能塞 HTML 元素**。第一版城市卡片用了 `<div>` 做行布局，浏览器不渲染，文字全被挤到画布左下角。改成纯 `<text>` 手工定位。
3. **右侧面板会把地图压扁**。第一版用 flex 分栏，地图只剩 730px，`viewBox` 1200 缩到 0.6 倍后 12px 的字只剩 7px，完全看不清。改成面板绝对定位浮在图上，地图占满宽度。
4. **气泡被自己的重绘冲掉**。`loadMap()` 里原本先弹气泡再 `renderMap()`，而后者重写 `innerHTML`，气泡瞬间消失。改成先渲染再弹，并在重建时把正在显示的气泡接回来。
5. **右侧面板盖住了整个亚洲**。面板 300px 浮在右边，东京/上海/香港/首尔/台北全被压在下面。解法是给视图状态加一条 `MAP_PANEL_GUTTER = 260`：`clampMapView` 允许额外左移这么多，初始 `tx = -200`，地图先往左推，亚洲就露出来了。配合把首尔、悉尼、东京的标签改成朝左展开，20 个标签做到零遮挡。

## 全球事件中心

点右上角「事件中心」进入（`#/events`）。两个部分：

### 即将公布（宏观日历）

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| FOMC 利率决议 | 美联储官网 | 解析官方日历，2021–2027 共 53 次会议，自动标记哪几次带 SEP 与点阵图 |
| CPI / 非农 / PPI / PCE / GDP / 零售 | 美国劳工统计局（BLS） | 抓官方发布日程，标题带「数据所属月份」 |

两个实现细节值得记一笔：
- **BLS 页面有反爬**（直连 403），走文本代理读取官方页再解析日历表格。
- **BLS 日历表格最后一行跨到下个月**（`| 30 | 1 | 2 | 3 | 4 ... |`），如果直接取格子里的数字，"12 月 4 日的非农"会被算成"11 月 4 日"。所以解析时一旦日期回退就月份 +1。
- 同一指标一个月可能出现两次（例如政府停摆后补发上月数据，2026-11-02 发 9 月、11-06 发 10 月），所以标题里标了数据所属月份，不是重复条目。

### 实时事件流

聚合三个源：**金十数据**（最快，带「重要」标记）、**新浪财经 7×24**、**华尔街见闻**（最专业）。只保留与市场相关的条目。

打分逻辑（这里踩过坑）：
- 最早版本用「关键词命中数量累加」，结果「红利低波ETF…半日成交2.46亿」因为在一段话里同时提到货币政策/通胀/能源/中国政策而排到第一，真正的「日本央行鹰派按兵不动」反而靠后。
- 改成：**标题命中的主题才算强命中**（正文命中打 7 折）、主主题取权重最大者、次要主题只做 ×0.35 加权、汇总稿/营销稿（`汇总|一览|早报|净值|领跑|半日成交` 等）直接丢弃、弱相关（主主题权重 < 1.5）丢弃。
- **排序按时间倒序**，不是按分数。事件中心的第一性是「实时」，影响等级只用于视觉高亮和筛选。

主题分类 12 类：货币政策、通胀、就业、地缘政治、能源、贵金属、加密资产、中国政策、权益市场、债市、汇率、宏观数据。每条带上受影响标的，可直接对照看板。

### 噪声过滤：误报比漏报更伤

实测 276 条事件里有 26 条是「选举 / 风暴」表面的假高影响稿，且**几乎全被打成 `high`**，直接污染排序和地图冲击弧线。两类修法：

**1. 券商研报稿一律丢弃。** `目标价 | 维持…买入/增持 | 评级上调/下调 | 首次覆盖 | 主力资金净 | 龙虎榜` 命中即丢。典型误判：*"花旗：巴西选举可能给中国国际海运集装箱带来轻微正面影响。维持对该H股的评级为买入，目标价12.3港元"* —— 因为标题有「选举」被判成 high 地缘政治并连上黄金/原油/VIX。

**2. 多义词加语境排除**（`sanitizeAmbiguousContext`）。同一份词表里「风暴袭击欧洲」和「空袭伊朗」都命中「袭击」，但前者没有价格传导路径：

| 原文片段 | 清洗后 | 结果 |
| --- | --- | --- |
| 风暴袭击欧洲 影响多国电力供应 | 气象灾害侵袭欧洲 | 不再判地缘政治 |
| 以防长称无意在选举前袭击伊朗 | 保留「袭击」 | 仍判地缘政治 ✓ |
| 消费升级 / 产业升级 | 产业演进 | 不再命中「升级」 |
| 董事会选举 / 换届选举 | 公司治理 | 不再命中「选举」 |

**3. 「选举」单列成低权主题**（`politics`，weight 1.2，不挂任何标的）。选举本身不是价格传导事件，绝大多数是政治八卦和民调播报；单列后它仍会出现在事件流里可看，但不会被判 `high`、也不会连冲击弧线。真正有传导意义的（关税、制裁、战争）仍在 `geopolitics`（weight 3）。

### 走势图上的事件标注

标的详情页的走势图会把相关宏观事件打成竖虚线（FOMC 红、CPI 黄、非农蓝），用来解释「这段为什么突然动」。

### LLM 语义分类

关键词分类有天花板，所以加了 LLM 复核，标记为 `AI` 的条目是 LLM 判定的，`关键词` 的是规则兜底。

**为什么不用 `dsh headless`**：它每次都会完整加载 agent 栈，实测单次 `inputTokens` 24 万、耗时 28.8 秒、`outputTokens` 只有 1（被 max-tokens 掐断）。对每分钟一轮的新闻流完全不现实。

**喂的是标题 + 正文摘要**：只给标题时，「某公司中东项目仍有交付」会被判成地缘冲突；带上正文前 80 字就能看出是公司动态。代价是 token 翻倍（约 200 个 prompt token/批）。

同时让模型输出 `region`（us/cn/eu/uk/jp/me/asia/latam/africa/global），作为地图落点的依据。关键词分类时也会用地理词表先兜一个底。

**实际做法**：从 dsh 的 web profile 配置里直接提取网关参数，然后走同一个 provider：

```js
// 读 ~/.dsh/profiles/web/cordis.patch.yml，拿到 baseURL / apiKeyEnv / 模型列表
// key 从 ~/.dsh/.credentials.yaml 的 refs 段取
// 模型优先 cline-pass/deepseek-v4.1-flash-1017
```

这样 dsh 换了 provider 或模型，看板会跟着走，不用改代码。实测 3.4 秒、108 prompt tokens、成本约 $0.0003/批。

几个踩过的坑，都写进代码注释了：

1. **响应结构不是标准 OpenAI** —— 网关把结果包在 `data` 里（`j.data.choices[0].message.content`），直接读 `j.choices` 会一直拿到空字符串。
2. **reasoning 模型会先思考** —— `max_tokens` 给 1600 时 content 会被思考内容挤掉，提到 2500 才稳定。
3. **模型会返回列表外的值** —— 比如 topic 给「融资」「原油供应」、symbol 给「wti」。做了别名归一（wti→oil、纳指→ndx100、A轮融资→无关），映射不到的丢弃。
4. **连续请求会被网关 429/500** —— 改成每批 15 条、批间停 1.2 秒、单批失败重试一次。
5. **JSON 可能被截断** —— 标准解析失败就退化成逐个抠 `{...}` 片段，尽量不浪费这一批请求。
6. **缓存与异步更新会打架** —— LLM 在后台跑，但事件缓存还在有效期内，前端会一直看不到 AI 结果。所以缓存命中时重新 `applyLlmResults` 盖一次。

下半场四个模块：

1. **相关性矩阵**（13×13）：日收益率的两两相关性，红色正相关 / 蓝色负相关，深浅表示强度。可切 20/60/120/250 日或全部窗口，也可切**日频 / 周频**。
2. **谁在影响谁**：领先滞后扫描。只在「滞后相关明显强于同期相关」时计入，单位随频率变化（日/周）。例：国际金 → 沪金 1 日（+0.594），美股/铜 → 上证 1 日。
3. **滚动相关性**：点矩阵任一格子，看这两个标的 40 期滚动相关性怎么随时间变化（相关性是时变的，单看一个数字会骗人）。
4. **归一化走势对比**：勾选任意标的，起点归一化为 100 叠图比较。

风险偏好指标（顶部徽章）用的是**波动率标准化后的 Z 值**，不是收益率简单平均：

- 把 BTC / 标普 / 美元 / 黄金的日收益等权相加，指标基本等于「BTC + 原油指标」—— BTC 日波动约 3.5%，美元指数只有 0.35%，差 10 倍，标普和美元的信号会被噪声淹掉。所以先算 `z = r / σ60`（σ 用前 60 期、剔除当期，避免极值同时污染分子和分母），再取均值，每个资产贡献一个标准差单位。
- **风险篮子不含原油**：供给冲击下油涨股跌是典型滞胀型 Risk-Off，把原油算进风险端会把方向判反。改用 COMEX 铜作工业需求代理。
- **避险篮子 = VIX + 美元 + 美债（按债券价格口径）**：收益率上行 = 债券下跌 = 避险走弱，所以美债的 z 取反号。黄金以美元计价，日常与美元负相关，塞进同一个篮子会互相抵消。
- **跨日错位会显式标出来**：BTC 周末交易、各市场时区不同，成员落在不同交易日时页面标「跨日错位」并把成员日期列出来，而不是假装对齐。实测当前就是 `成员日期 2026-10-23 / 2026-10-26` 混合状态。

### 利率类标的如何与其他资产同轴比较

归一化对比里所有曲线都按 `v *= exp(r)` 累乘。但美债 10Y 的输入是**百分点差**（+0.05 = 5bps），不是收益率 —— 直接丢进 `exp()` 有两个错：

1. **量纲差两个数量级**：累计上行 100bps 会算成 `exp(1.0) = 2.718`，即净值 271.8、显示 +171.8%，把其他资产全压扁。
2. **方向反了**：收益率上行意味着债券价格下跌，图上却画成上涨。

所以对 `kind === 'rate'` 的标的按久期近似 `ΔP/P ≈ −D·Δy` 折算（`D = 8` 年），图上画的是**债券价格**，图例标「久期折算」。

实测（120 个交易日窗口）：

| 口径 | 10Y 终值 | 显示 | 同期标普 |
| --- | --- | --- | --- |
| 直接 `exp()` | 177.2 | **+77.2%** | +5.9% |
| 久期折算 | 95.5 | **−4.5%** | +5.9% |

10Y 期间累计上行 57bps，×8 年久期 ≈ −4.6% 债券价格变动，与折算结果一致。

| 组合 | 日频 | 周频 |
| --- | --- | --- |
| 国际金 ~ 沪金 | +0.476 | **+0.721** |
| 沪金 ~ 上证 | +0.484 | **+0.104** |

### 背离检测：拿实盘检验理论

对每条边，比较「理论的 `sign`」和「近 20 / 60 期实测滚动相关」，两个条件任一命中即判背离：

```
条件 A（单期剧烈异动背离）：两端当日波动均 > 0.5σ，且 sign(rA·rB) ≠ sign
条件 B（短期趋势背离）：sign(ρ20) ≠ sign，且满足其一：
  - |ρ20| ≥ 0.45（20 样本下 |t| > 2.13, p < 0.05，单窗已统计显著）
  - |ρ20| ≥ 0.35 且 sign(ρ60) ≠ sign（60 期同向反号二次确认，滤除单月随机游走噪声）
反之，若同日方向一致，或 |ρ20| ≥ 0.25 且同号 → 判定「走势与机制一致」（只表达观测一致性，不表示因果已证实）
```

σ 用近 60 期的样本标准差；`ρ20` / `ρ60` 用**最近 20 / 60 个共同交易日**（下一节解释为什么不是「最近 20 条记录」）。

沙盘选好震源后还能选**冲击条件**（原因未分类 / 供给受阻 / 需求增强）：同一「原油大涨」在不同原因下参与的渠道不同，条件外的边不参与传播并给出排除理由。这里只做路径结构的筛选，不产出幅度、概率或先后顺序。

「当期」比较一律用**共同日期配对**：取最后一个双方都有观测的位置，并把该日期返回给界面。一侧最新观测更晚时（跨时区、休市、数据晚到），机理卡会显示「有一侧最新观测更晚，未参与比较」，不会把不同日期当成同一天。

页面顶部实时横幅会自动挑出「权重最高、背离最狠」的那一条，点「查看」直接选中该边并联动下方全部定量模块。横幅与右上角徽章**扫同一个 18 条全量集合**（不只是罗盘上的 16 条主干边）—— `E16 国际金→沪金`、`E18 WTI→布伦特` 这两条 `weight 3` 的同源定价锚一旦背离，意味的是汇率异动或航运割裂这类极端行情，必须能弹出来；否则会出现「徽章写着 1/18 却点不到」。点「查看」时顺带清掉当前剧本并切回罗盘，保证右侧出现的是这条边的机理卡而不是剧本叙事。右上角常驻 `背离 N/18`，右侧机理卡片同时展示 `250 期 / 60 期滚动 / 20 期滚动` 三档期限结构。

实测（`generatedAt = 2026-10-27T01:59Z`，日频 250 日窗口；条数会随滚动窗口漂移，下面只是那一刻的快照）：

| 状态 | 条数 | 例子 |
| --- | ---: | --- |
| ✓ 走势与机制一致 | 8 | E14 标普~VIX `ρ20 −0.88 / ρ60 −0.69 / 250期 −0.69`、E17 标普~纳指 `0.91 / 0.90 / 0.90` |
| ⚡ 观测方向不同 | 2 | E06 10Y~纳指 `ρ20 +0.54 / ρ60 −0.08`（理论 −，**单窗显著**分支）、E15 VIX~金 `ρ20 −0.41 / ρ60 −0.51`（理论 +，**持续确认**分支） |
| ○ 未见明显偏离 | 8 | E08 油~金 `ρ20 −0.34 / ρ60 −0.11`（理论 +，ρ20 反号但没过 0.35 且 ρ60 同号 → 按噪声处理）、E02 美元~油 `−0.09`（方向对但太弱） |

三条自检：

1. **两条背离正好各走一个分支**：E06 的 ρ60 = −0.08 与理论同号（中途反弹），只有单窗 0.54 ≥ 0.45 这条路径能抓住它；E15 的 ρ20 只有 0.41，靠 ρ60 = −0.51 同向反号才确认。只留单层判据的话，这两条会各漏一条。
2. **E08 被新阈值滤掉了**（旧规则 `|ρ20| ≥ 0.28` 会把它算成背离）。这正是收紧的理由：ρ20 反号但 ρ60 同号、且 |ρ20| = 0.34 < 0.35，属于单月随机游走的典型形态。
3. E14/E17 的数字落在设计时的常识区间（−0.75 / >0.92），说明取值口径没跑偏。

### 一个必须记住的坑：ρ20 不能用「最近 20 条记录」

`/api/macro` 的 `recent.dates` 是 13 个市场交易日的**并集**（341 条覆盖约 250 个交易日），每条记录对单个品种约 25% 是 `null`。按位置截最后 20 条再找共同样本，实测只剩 **10** 个，直接跌破 12 的最小样本阈值 —— 18 条边的 `ρ20` 会**全部**变成 `null`，整条边只剩单期异动一种判据。

正确做法是先取成对非空、再截尾 20 个，与后端相关性矩阵的 pairwise 口径一致。改完之后 18/18 条边都有 `ρ20`，背离判定才真正跑起来。

### 一个必须记住的坑：胶囊落点不能靠手调

16 条边中不少要绕开中转节点（原油→标普必须绕开铜、纳指→BTC 必须绕开上证），胶囊宽度 64~83px 又比相邻节点净空还宽。手工调 `bend` 的结果是「看着不撞、渲染出来压住节点」。

做法是写一个**离线排版求解器**（`/tmp/mg-solve.mjs` 之外的那套逻辑已固化进常量）：对每条边在 `bend ∈ ±144`、`t ∈ 0.2~0.8` 上联合搜索，代价函数 = 胶囊压节点 ×500 + 胶囊互相压 ×1000 + 曲线穿过无关节点 ×260 + 画布出界 ×1200 + 底部留白 ×150 + `|bend|`/`|t−0.5|` 正则项，按权重降序贪心 + 3 轮松弛迭代。解出来的 `bend`/`t` 直接写回边定义，运行时不搜索。

排版审计直接读渲染出来的 SVG（不是几何探针），避免「探针说没撞、实际撞了」：

```
渲染中的节点 10 个 / 胶囊 16 个
审计：干净
```

另外，底排 4 个节点横向拉到 118~742（净空 96px），是为了让最宽的 83px 胶囊能直接落在线段上。净空不到 96 就得靠 `pill.lead` 引线把胶囊挑出线外，那个「挑出来再连回去」的引线在相邻节点之间很难看。

### 沙盘推演：一阶、二阶与多空交织

从 6 个候选震源（原油 / 美元 / 10Y / VIX / 铜 / 纳指）选一个，指定大涨或大跌，沿 16 条主干边做两跳传播，`dir = 冲击方向 × 边符号连乘`。

同一个标的被两条方向相反的路径命中时标琥珀色「多空交织」。实测「原油大涨」：

```
黄金：一阶 WTI →[+ 通胀驱动]→ 利多 ↑
      二阶 WTI →[+ 通胀与加息]→ 10Y →[− 机会成本]→ 利空 ↓
→ 3 利多 / 2 利空 / 1 多空交织
```

这正是这个视图存在的意义：**看到琥珀色，应该理解为「方向还没定」，而不是「一定涨/跌」**。短期通常交易一阶（通胀与地缘），中期若二阶兑现（实质紧缩）则反向。

### 为什么全局图没有直接用 dagre / elkjs 自动分层

因为实测不行，`npm run lab`（`tools/layout-lab.mjs`）可复现：

```
=== dagre + node.rank（rank 被忽略） ===      === elkjs layered + partitioning ===
  y=39:  us10y                                  y=24:   us10y
  y=197: dxy          ← 同为「定价之锚」        y=188:  dxy          ← 同样裂开
  y=355: oil, copper                            y=352:  oil, copper
  y=513: sh000001, sp500                        ...
  （共 6 层）                                    （共 7 层）

=== 本项目 layoutTiered（声明层级 + 交叉数局部搜索） ===
  y=34:  dxy, us10y     ← 同一生态位同一行
  y=208: oil
  y=218: copper
```

- dagre 的 `node.rank` 属性被 `network-simplex` ranker 直接忽略；
- dagre `compound`（把四个生态位当 cluster）能算出簇框，但排成 925×1273 且簇相互嵌套错位；
- elkjs 的 `partitioning` 只保证 partition 之间的先后，不保证同 partition 同行。

这张图本身有 3 个因果闭环（油→10Y→美元→油 等），**拓扑层级不唯一**；业务上要的是「四层生态位」而不是「最长路径层数」。所以层级由知识库声明（`tier` 字段），算法只负责行内顺序与间距 —— 行内顺序用「相邻交换 + 交叉计数」局部搜索（dagre ordering 阶段同款算法）。这仍然是自动布局：`bend` / `pill.t` 这些手调坐标全部删掉了，折点交给 `manhattan` 路由器算。

## 专业口径说明

这些细节直接影响数字能不能拿来用，所以单独写清楚：

- **涨跌基准**：股票/指数/现货用「昨收」，期货用「昨结算」（`priceBasis: settle`）。WTI、布伦特、伦敦金都按昨结算算涨跌——结算价和收盘价在换月、结算日会差出可观幅度。详情页的指标卡会直接写成「昨结算」。
- **年化波动率**：股票/商品按 252 个交易日年化，加密按 **365**（7×24 无休）。BTC 用 √252 会把波动率低估约 17%（51% vs 实际 66.6%）。市场画像见 `MARKET_PROFILES`。
- **最大回撤**：收盘价口径，记录峰值日与谷底日。实测值与历史事件吻合：标普 −56.8%（2007-10 → 2009-03）、上证 −72.0%（2007-10 → 2008-11）、BTC −83.2%（2017-12 → 2018-12）、WTI −91.1%（2008-07 → 2020-04）。
- **市场状态**：按北京时间判断各市场是否在交易时段内（上金所含夜盘 20:00–02:30，美股 21:30–04:00，加密 24×7），详情页右上角显示「交易中 / 已收盘 / 24×7」。
- **走势图**：可切线性/对数坐标。20 年这类长时间跨度建议用**对数**——线性坐标会把早期波动压扁，看不出百分比级别的变化（黄金 2006 年 144 → 现在 862，线性下图左半段几乎是平的）。
- **均线与成交量**：MA20/MA60 叠加在主图，成交量单独一副图并按当日涨跌着色。

### 已知的数据局限

- WTI / 布伦特用的是**当月连续**合约（`CL00Y` / `B00Y`），换月处存在非真实跳空。看一两个月的短期走势时要注意这点，长期年线不受影响。
- 美股指数（`gb_$inx` / `gb_$ndx`）是新浪的延迟行情，非交易时段就是上一交易日收盘，页面显示「已收盘」而非实时。
- 标普500 / 纳指100 的成交量来自东财，是指数口径的汇总量，不等于可交易标的的量，只宜横向比较、不宜当作个股成交量解读。
- 现货黄金 `122.XAU` 的成交量恒为 0，所以国际金价详情页不画成交量副图。

## 涨跌幅口径

涨跌幅优先用「涨跌额 ÷ 昨收/昨结算」自行计算，而不是直接采用上游给的百分比——上游常把它四舍五入到两位小数，导致纳指100 这种 -0.004% 的微幅变动被显示成 `-0.00%`。前端在幅度小于 0.01% 时会多保留一位小数。

比特币是 24 小时口径；A 股、美股、内盘期货为各自「上一交易日的昨收/昨结算」。

### 一个必须记住的坑

**FRED 对伪装成 Chrome 的 UA 会挂起连接**（40 秒超时），换 Node 默认 UA 则 1.2 秒返回 269KB。所以 `fetchRaw` 加了 `omitUa` 选项，FRED 走它。

### 落盘缓存

`data/daily/<id>.json`，新鲜窗口 8 小时：

- **8 小时内**：直接读盘，**一个源都不打**
- **过期**：请求源；源全失败则回退旧缓存，并把 `hit: 'stale'` 和陈旧时长透给前端
- **正常**：拿到就落盘（`tmp` + `rename` 原子写，避免进程被杀留下半截 JSON）

详情页在 `stale` 时会显示：「数据源暂时不可用，当前显示的是 N 天前落盘的日线缓存（截止 X）」，并列出每个源的失败原因。

### 全球指数的历史缺口

DAX / CAC / KOSPI / NIFTY / ASX / TSX / TWII / N225 / BVSP / FTSE 这 10 个**没有可靠的免费历史源**：腾讯只认美/港/A，Nasdaq 只有 NDX/COMP，FRED 只覆盖美国。目前靠「实时报价（CNBC）+ 本地缓存逐日积累」，跑几个月自然就有历史。这是数据天花板，不是实现缺失。

## 隔夜复盘

A 股 15:00 收盘后，美股/美债/美元/黄金/原油还在走。第二天开盘前最想知道「昨晚这些东西各走了多少」。

实现方式是**本机快照差分**，不依赖任何外部源，因此不会因为限流失效：

1. `getQuotes` 每次成功后落一版快照到 `data/snapshots.jsonl`，**节流 5 分钟**（15 秒一版会让文件半年就上 GB）
2. `GET /api/briefing` 取「上一个自然日的最后一条」作基准（按 `Asia/Shanghai` 切日），逐标的算价差与幅度，按 |幅度| 排序
3. 样本不足时返回 `status: collecting`，如实说「还在积累」，不编造

前端在顶栏点「隔夜复盘」弹出浮层。时间显示转成本机时区（快照本身是 ISO/UTC，直接切片会显示成 UTC 钟点）。

## 详情页两处口径修正

**近 1 日 chip 一直缺失。** 后端 `perf.d1` 填的是 `last.pct`，而 FRED / Yahoo 这类源的行里没有 `pct` 字段，前端 `.filter(v => v != null)` 就把它滤掉了 —— 所以 chip 一直是「近1周」开头。改成走 `perf(1)`：有实时报价时直接取 `quote.changePct`（它天然是「相对昨收」），现在 `perf.d1` 与页面顶部涨跌幅**逐位相同**。

**52 周高低全是 `—`。** `Math.max(...[])` 返回 null。根因还是 FRED 只给收盘价、没有 high/low。现在无 high/low 时退回收盘口径，并把实时价并进极值集合。修完后标普 52 周高低从 `— / —` 变成 `7,818.93 / 6,343.72`。

顺带：区间基准日期改用 `max(日线最后日期, 现在)`，否则 FRED 滞后 2 天时「近1周」算的其实是「上周对再上周」，标题和内容对不上。

## 本地存储改用 SQLite

`node:sqlite` 是 Node 22+ 的内置模块，**零依赖**，正合适这个项目。单文件 `data/kanban.db`，WAL 模式。

| 表 | 用途 | 主键 |
| --- | --- | --- |
| `daily_bars` | 日线 OHLCV | `(id, date)` |
| `daily_meta` | 每个标的的源、落盘时间、条数、起止日 | `id` |
| `snapshots` | 隔夜复盘用的报价快照 | `(at, id)` |
| `kv` | LLM 分类缓存等杂项 | `k` |

设计要点：

- **整段替换而非增量插入**：源可能回补历史，留着旧行会和新的重复。所以 `writeDailyCache` 在一个事务里 `DELETE` 再批量 `INSERT`。
- **`readDailyCache` / `writeDailyCache` 签名没变**，调用点（详情页、宏观页）一行都不用改。
- **一次性迁移**：`migrateLegacyStorage()` 把旧的 `data/daily/*.json`、`snapshots.jsonl`、`llm-cache.json` 导入库，用 `kv['migrated-sqlite-v1']` 打标记只跑一次。原文件保留不删，方便回滚核对。

实测迁移结果：**日线 37,390 行 / 快照 300 行 / LLM 缓存 306 条**，8 个标的的源与日期区间全部正确。

## 审阅提出的 5 个 Bug 修复

**1. 20 日窗口下 Risk-On/Risk-Off 整体消失。** `zOf` 需要 ≥40 期样本，而 `series` 存的是被 `windowSize` 截断后的序列 —— 切到「20日」时全部返回 null。修法是单独留一份近 65 期原始变动给 z-Score 专用（`zSeries`），与显示窗口解耦。顺带把定档阈值从 ±0.2σ 调到 **±0.5σ**（±0.2σ 只覆盖正态中间 16%，几乎天天触发）。实测三个窗口都稳定输出 `Risk-Off / -1.86σ`。

## 领先滞后：双向扫描 + 全检验族 Newey-West BH

这是本轮最重要的统计修正，两个错都在同一段代码里。

**错误一：单向扫描。** `leadLagScan` 只测 `lag = 1..5` 的 a→b，而配对循环是 `i < j`。`MACRO_UNIVERSE` 里 `gold-cn` 排第 2、`dxy` 排第 10，于是**只测了「沪金领先美元」，真正符合宏观逻辑的「美元领先沪金」100% 被跳过**。改成每个滞后同时检验两个方向（`lag > 0` = a 领先 b，`lag < 0` = b 领先 a）后：

```
美元 → 沪金   lag=1  corr=-0.327  sameDay=-0.105  q=0.000  ✓显著
```

这条在修复前根本不会出现在结果里。

**错误二：先筛后校正。** 原来是先按 `gain>=0.04` 和 `|corr|>=0.15` 筛剩几个配对，再对这几个做 BH。被筛掉的假设同样参与了「碰巧显著」的机会，不纳入族里会让 q 值偏小。现在先把 `C(13,2)×2方向×5滞后 = 780` 个假设全部算出来一起做 BH，再筛展示。

**顺带：普通 t → Newey-West t。** 日频金融序列有波动率聚集，残差自相关会系统性放大 t 值。改成对回归斜率做 HAC 方差估计，带宽用 Newey-West 经验值 `floor(4·(n/100)^(2/9))`，Bartlett 权重保证半正定。

修完后的前几名（窗口 250 日）：

| --- | --- | --- | --- | --- | --- |


## 第三步：交易所原生时区 + 跨源基差护栏

### 时区：从写死北京时间改为交易所本地时区

原来的 `MARKET_PROFILES` 全部按北京时间写死，有两个必然出错的地方：

1. **夏令时**。美股冬令时北京时间 22:30 开盘、夏令时 21:30，写死一个值一年错半年。更麻烦的是**欧洲 10 月最后一个周日切冬令时、美国要等到 11 月第一个周日** —— 那两周里两国是错开的，任何单一偏移都不能同时正确。
2. **跨午夜的周几归属**。北京时间周六 02:00 其实是美东周五 14:00（盘中），而北京时间周一 02:00 是美东周日 14:00（休市）。按北京时间的 `day` 判断两个都错：一个把盘中判成休市，一个把休市判成盘中。

改成每个 profile 带 `tz`、时段写交易所本地时间后，股票时段都不跨午夜，这两个问题同时消失。

```js
function localClock(tz, now) {
  // hourCycle 必须显式给 'h23'：en-US 默认在午夜会格式化成 "24:15"，解析出 1455 分钟
  new Intl.DateTimeFormat('en-US', { timeZone: tz, weekday: 'short',
    hour: '2-digit', minute: '2-digit', hourCycle: 'h23' })
}
```

`GLOBEX_ET` 抽成常量，`intl-futures` / `us-rate` / `fx` 共用（周日 18:00 ET 开盘、周五 17:00 ET 收盘、每日 17:00–18:00 结算）。上金所夜盘拆成 `[1,2,3,4] 20:00–24:00` + `[2,3,4,5] 00:00–02:30`，不再依赖跨午夜判断。

### 基差护栏：期货价不许污染现货分时

`gold-intl` 主源是 `sina:hf_XAU`（伦敦金现货），兜底是 `sina:hf_GC`（COMEX 期金，通常高 $15–30）。`gold-cn` 主源 `gds_AU9999`（上金所现货），兜底 `nf_AU0`（沪金主连，有期现基差）。

主源偶发一次超时，兜底期货价就被 `pushHistory` 写进同一个分时数组；15 秒后主源恢复，卡片右侧的迷你走势图就留下一根**永久的脉冲断崖针**。

双层护栏：

```js
// 第一层：显式标记跨合约代理源
const basisProxy = (src) => ({ ...src, basisProxy: true });
// gold-intl: [sinaSpot('hf_XAU'), basisProxy(sinaSpot('hf_GC')), goldApi('XAU')]
// gold-cn  : [sinaSpot('gds_AU9999'), sinaSpot('gds_AUTD'), basisProxy(sinaFutures('nf_AU0'))]

// 第二层：pushHistory 拦截
if (meta.basisProxy) return false;                      // 代理源一律不写分时
if (prevSrc && prevSrc !== meta.source
    && Math.abs(price - prev.p) / prev.p > 0.0025) return false;  // 跨源跳变 > 0.25% 拦截
```

**实测验证**（把 `hf_XAU` 改成 `hf_BOGUS` 逼降级）：

```
第 1 次: price=4033.028  src=sina:hf_GC  basisProxy=True  history=240  last={p: 4017.55}
第 2 次: price=4033.028  src=sina:hf_GC  basisProxy=True  history=240  last={p: 4017.55}
第 3 次: price=4033.028  src=sina:hf_GC  basisProxy=True  history=240  last={p: 4017.55}
```

现价切到期货 **4033.028** 正常显示（差 0.385%，远大于 0.25% 阈值），但 `history` 稳定在 240 点、最后一点仍停在现货 **4017.55** —— 没有脉冲针。

恢复 `hf_XAU` 后：`src=sina:hf_XAU`、`basisProxy=False`、最后一点更新为 **4018.81**（现货价，不是期货 4033）。

1. **全局图不用 dagre/elkjs 自动分层**，改为「知识库声明 tier + 行内交叉数局部搜索」。原因见上一节的可复现实验：两个引擎都会把同为「定价之锚」的 `dxy` / `us10y` 拆到不同行。`elkjs` 因此降级为 `devDependency`，只给 `tools/layout-lab.mjs` 做离线对比，不进浏览器包（省 1.6MB）。单点思维导图仍然用 dagre 的 `rankdir:'LR'`（那本来就是棵树，dagre 排得比手算稳）。
2. **不整站迁到 `dist/`**。这个项目有一条硬约束是「双击就开、零安装」；整站切 Vite 意味着没跑过 `npm run build` 的机器打开就是白屏。所以 Phase 1 只把 X6 那块拆成 `public/vendor/macro-flow.js` 懒加载，其余原生前端原样保留，加载失败自动回退手绘 SVG。等 Phase 2 把五大视图搬完再切 `dist/` + 服务端 `dist → public` 顺序回退。

4. **流光用叠加边**。X6 只把算出来的路径写给 `selector: 'line'` 那一个 `path`，同一条边里再写第二个 `path` 是静态的。所以每条边额外加一条 `flow-<id>` 叠加边承载流动虚线。

### 施工中踩到的四个坑（写下来省下一次）

### 生命周期收敛：从「每个分支手动清理」到「视图自己管自己」

原 `route()` 是 88 行 if-else 阶梯，每加一个视图要在**每个**分支补「隐藏 + 清空 + 停表」。五个视图 = 四份重复清理，漏一句就是泄漏点。现在每个视图实现 `mount()` / `unmount()`，router 只做「除目标外全部 unmount，目标 mount」。

**两个真实泄漏，修前修后都量了：**

| 泄漏 | 修前（单体） | 修后（拆分） | 怎么量的 |
| --- | --- | --- | --- |
| X6 画布未释放 | 5 轮进出泄漏 **5** 个 `ResizeObserver` 与画布实例 | 5 轮进出 → 创建 5 / `disconnect()` **5** | monkey-patch `ResizeObserver` 计数构造与 disconnect |
| `llmRetry` 未清 | 离开事件页后 **仍补发 1 次** `/api/events` | **0 次** | 造一份 `llm.pending = true` 的载荷，进入后立刻离开，数 9 秒内的请求 |

> X6 那条一开始没生效：`destroyMacroFlow(host)` 的 host 必须是画布真正挂载的 `#macro-graph-host`，而不是它的父容器 `#macro`——传父容器时 WeakMap 取不到，dispose 静默空转。这条已经写成断言（`tests/client-modules.test.js`）。

### 等价性怎么证的（比「看着一样」硬）

前两次尝试都失败了，原因是数据在漂移：

1. 跨次加载直接比 DOM 哈希 → **不稳定**：价格、时间、sparkline 路径坐标每次都变（同模式连跑两次也不一样）。
2. 归一化掉数字后再比 → 仍然不稳定（坐标精度位数会变）。

最后用**冻结数据回放**解决：用 CDP `Fetch.fulfillRequest` 把 `/api/*` 全部替换成提前抓好的快照，再把 `Date` 也冻结成定值，两种实现渲染同一批数据。此时归一化 DOM 哈希**逐字节相同**：

| --- | ---: | --- |
| `#rows` 列表 | 583 | `b57895cc` |
| `#detail` 详情 | 3873 | `3b8ce83c` |
| `#map` 地图 | 464 | `ecfbd9ad` |
| `#events` 事件 | 593 | `28821a82` |
| `#macro` 传导图 | 1142 | `cdf72aed` |

同一份 harness 跑两遍结果一致（确定性已验证），所以这五组哈希是可复现的验收基准。

### 边界纪律（写进 `tests/client-modules.test.js`，12 条断言）

- 所有相对 / 绝对 import 的路径都必须真实存在 —— 拆分过程中这是最高频的错（`./worldmap.js` 从 `src/client/views/` 解析过去就指向不存在的位置，`MAP_SIZE is not defined` 就是这么炸的）；
- 页面骨架的 DOM 引用只能在 `shared/dom.js` 里 `getElementById`；
- 只有 `router.js` 监听 `hashchange`，四个视图都必须实现 `mount` / `unmount`；
- 每个 `unmount` 必须调用自己的 `stopXxxTimer`，`events.unmount` 必须清 `llmRetry`，`macro.unmount` 必须 `destroyMacroFlow` 且用 `#macro-graph-host` 做 key；
- 共享可变状态只能挂在 `store` 上，视图里不准另起 `let`；
- `public/app.js` 只能是一行转发。

### 零构建怎么保住的

`public/app.js` 只剩 `import './../src/client/main.js';`，浏览器原生加载 ES 模块。`server.mjs` 的 `serveStatic` 加了一段 `/src/client/**` → 仓库 `src/client/` 的映射（只开放这一个子树，越界与 `../` 穿越都已被拦），所以**不装依赖、不打包也能跑**。Phase 3 切到 `dist → public` 回退后，这段映射会被替换成构建产物路径。

## 快照跳变护栏：修掉 `sina:int_*` 僵尸价污染

### 事故与真因（实测，不是推测）

`/api/briefing` 会间歇性出现 `+40.76%` 这种离谱值。查库得三个品种的极值跨度异常：

| 品种 | 低值 | 高值 | 跨度 |
| --- | --- | ---: | ---: |
| `n225` | `44946.64` | `63268.37` | 41.18% |
| `ftse` | `9284.83` | `10767.33` | 15.97% |
| `dji` | `46247.29` | `52361.58` | 13.22% |

**低值才是假的**。直接打接口验证：

```
$ curl -H 'Referer: https://finance.sina.com.cn' 'https://hq.sinajs.cn/list=int_nikkei'
var hq_str_int_nikkei="日经指数,44946.64,-408.35,-0.90";   ← 与库里的低值一字不差
```

`sina:int_nikkei / int_ftse / int_dji` 早已停更，但接口仍返回一年前的僵尸价（连涨跌幅小数位都冻结）。`GLOBAL_INDEX_DEFS` 给这三只指数配了 `em: '100.xxx'` + `sina: 'int_xxx'`，**东财偶发断连降级到新浪时，僵尸价就被写进快照**，而复盘拿它与东财的真实价做差 —— 差值不是「隔夜涨跌」，是跨源口径错位。

### 治写：`db/snapshots.js` 跳变护栏

`takeSnapshot(quotes, { maxJumpPct, maxJumpPctById, onSkip })`：与**最近 6 个刻度的中位价**比较，超阈值先挂起、连续两次都指向同一新价位才放行。

两个设计要点：

1. **`db/` 不反向依赖** —— 阈值由调用方按品种传入（`quotes.service` 传现成的 `MOVE_SUSPECT_PCT`），db 层保持不认识业务标的。`tests/db.test.js` 的分层断言继续成立。
2. **躲开「脏锚点死锁」** —— 这是单次比较的致命伤：若库里最新一条本身就是僵尸价，真实行情回来时反而会被当成 `+40%` 永久拒之门外。改用两次确认的迟滞后，真实价位第二次出现即被认定换挡。有单测专门守这条：先造一个「最新刻度全是僵尸价」的库，再验证真实价第二次能写进去。

### 治读：`buildBriefing` 跨源过滤

算完 `movePct` 后，若 `|movePct| > MOVE_SUSPECT_PCT[id] ?? 12`，该行不进简报，改记入 `dropped: [{ id, movePct, limit }]`。阈值复用报价层同一套「这个品种一天能动多少」的认知，不另立标准。

构造场景实测：

```
基准 n225=63268 → 最新 n225=44946.64
items: dji 0.00%
dropped: [{"id":"n225","movePct":-28.96,"limit":12}]
```

### 验证

| 项目 | 结果 |
| --- | --- |
| 单测 | **265 passed**（新增 7 条护栏测试） |
| 金标准 8 端点 | 仅 `briefing.dropped` 新增字段，**所有业务叶子未变** |
| 真实库 `/api/briefing` | 23 项全在 ±1% 内，`dropped` 为空（最新刻度已干净） |
| 正常模式 | 6 个端点 200 / 首屏 23 行 / 0 console error |

> 顺带修掉一条既有测试的数据：它用 `1 → 2`（+100%）验证「时间刻度排序」，这种单步跳变现在会被护栏正当拦下。测试意图是排序，不是「任意价格都允许写入」，故改为同量级波动并注明原因。

### 治本（独立提交）：摘掉整族 `sina:int_*`

护栏让它无害，但僵尸源仍在降级链里。更彻底的做法是摘源 + 换活源：

| 标的 | 原主源（僵尸） | 现值 | 现源 |
| --- | --- | ---: | --- |
| `n225` | `sina:int_nikkei` 44946.64 | **63268.37** | `cnbc:.N225` |
| `ftse` | `sina:int_ftse` 9284.83 | **10662.22** | `cnbc:.FTSE` |
| `dji` | `sina:int_dji` 46247.29 | **52361.58** | `cnbc:.DJI` |
| `bvsp` | `sina:int_bovespa` 145446.70 | **176608.23** | `cnbc:.BVSP` |
| `hsi` | `sina:int_hangseng` | 23041.32 | `tencent:hkHSI` |

三处根因，逐个修掉：

1. **僵尸源秒回 200，永不降级** —— `bvsp` 只配了 `sina:int_bovespa` + `yahoo:^BVSP`，新浪每次都立刻返回一年前的死值，于是永远轮不到 Yahoo。首屏最后一行挂了一整年的旧价（库里 `spanPct = 0%`）。**摘掉僵户源比加护栏更根本**：护栏只是不让它进库，摘掉才是让它拿真数据。
2. **`tx` 配了却没用** —— `hsi` 有 `tx: 'hkHSI'`，但 `sources` 组装漏了 `...(d.tx ? [tencentQuote(d.tx)] : [])`，等于配了不生效。东财一断连就只剩 Yahoo 一条腿。
3. **新符号没登记批量清单** —— `cnbcQuote()` 查的是 `GLOBAL_CNBC_SYMBOLS` 预批量缓存，把 `.N225` 加进 `GLOBAL_INDEX_DEFS` 却不登记清单，表现是静默 `ok:false`（和当初 `parseCnbcQuotes` 漏 import 是同一类坑：不报错、只是没了）。

顺带发现护栏实现里一个真缺陷并修掉：两次确认的待定状态原本只在内存，而 `getQuotes` 每个进程只落一条刻度，**重启即清零 → 每次都算「第一次」→ 换挡永远确认不了**。改为落 `kv` 表后跨进程一致，实测第 1 轮挂起 4 个、第 2 轮全部写回（23 标的）。

验证：`dropped` 精确列出四个被污染的标的，幅度与最初事故吻合（`n225 +40.76%`、`ftse +14.83%`、`dji +13.22%`、`bvsp +21.42%`），19 项 + 4 项 = 23 自洽；`source` 变化恰好 5 个且只这 5 个；`int_*` 残留 0；268 passed。


## 传导图画布几何：底排分组带压线（E07）

底排的机理胶囊会贴着画布下沿被裁掉一点。量出来是**分组带越界 8px**：

```
画布高 708 | 最底卡片底边 684 | 最底分组带底边 716
```

分组带上下各外扩 `gapY * 0.34 = 32.6px`（把胶囊与折线转角圈进框选范围），但最后一行下方只有 `pad = 24px`，于是带底边越出 `32.6 − 24 ≈ 8px`，胶囊正好压在下沿。

修法：**只补画布、不动带几何**。宽度不用改（`CARD_GAP_X = 40` 对胶囊与正交折线两个 90° 转角是够的，实测无水平溢出），只把高度兜底到「最底带底边 + pad」：

```
画布 708 → 740 | 带底边 716 完整落在画布内，余量正好 24px（与其它边距一致）
```

选这个而不是把末行 `band.height` 系数从 `0.68` 提到 `0.9`，因为后者会让最后一条带的上下外扩不对称、与上面三条带的框选范围不一致；补画布则保持四条带几何完全统一。

验证：`tests/client-modules.test.js` 加两条几何断言（带必须在画布内、底部留白 ≥ pad、每条带覆盖自己那一行）；重建 `public/vendor/macro-flow.js` 后在真实画布上量 DOM，`bandOverflow: -56`（负值即在内），66 cells / 8 个带元素与改动前一致——说明只动了画布高度、没碰几何；12 项画布交互全 PASS，1920/1280/390 三档均无横向溢出。
